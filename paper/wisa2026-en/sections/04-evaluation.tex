On a 10-rule U256 capacity-run sample, Alive2 verifies the 6 without

\paragraph{Production Rule Coverage.} Using the canonical-LHS
methodology, the coverage run produces
\textbf{1966} Z3-admitted rewrite rules: \textbf{1856} from the
extended algebraic enumerator and \textbf{110} from pattern-template
instantiation. The pattern-template path starts from 2964 candidates,
of which 110 survive Z3 verification and deduplication against the
enumerator output and the existing rule file. On the 70
hand-designed production rules, the run matches \textbf{69/69} unique
canonical patterns---one commutative-twin pair, $\texttt{or}(x,y)$
versus $\texttt{or}(y,x)$, shares a single canonical representative
that both production names match---equivalently \textbf{70/70}
production rule names; the false-miss rate against the production set
is therefore \textbf{0/70}.

\paragraph{Scope of the Coverage Claim.}
\label{sec:coverage-scope}
{\sloppy
The enumerator's left-hand-side operator tops and constant pool were
tuned in light of an earlier 0/70 baseline that exposed mechanical
gaps (missing tops such as \texttt{not},
\texttt{select}, \texttt{shl}, \texttt{ushr},
\texttt{sshr}; missing small constants; structural-equality dedup of
$\texttt{and}(x,x)$). Reaching 70/70 therefore shows the production
rules lie inside an enumerable Z3-discharged search space, not blind
recall of an unseen target. Coverage is on canonical left-hand sides
only---enumerated right-hand sides are Z3-equivalent to their own
left-hand sides but are not syntactically required to match the
production rule's right-hand side. The tuned search space is broad
enough to contain every hand-designed rule, with 1966 members passing
Z3 admission; non-production members are not claimed to be useful
runtime rewrites.\par}

\subsection{End-to-End Performance}
\label{sec:perf}

After admission, the next question is whether the production rules produce
end-to-end speedups on real EVM workloads rather than merely enlarging the
pool of locally valid rewrites. We compare the rules-enabled build with
upstream main on evmone-bench; positive point-estimate speedup cases appear in
Figure~\ref{fig:speedup}.

\paragraph{Setup.} Intel Core Ultra 7 265K/Ubuntu 22.04; evmone-bench
paired \emph{2-side} mode (\texttt{upstream/main} vs.\ rules-enabled,
same session, $|\Delta_{\text{drift}}|<2\%$ gate), 20 runs (30 if CV $\geq3\%$),
bootstrap CIs ($B{=}10\,000$), pinned CPU, turbo off. Both binaries
use CI production flags including
\texttt{ZEN\_ENABLE\_JIT\_PRECOMPILE\_FALLBACK=ON} (no-fallback
not measured); the comparison spans two branches rather than toggling
rules in one binary, so per-rule attribution comes from the single-rule
audit (Sec.~\ref{sec:shadow-audit}). Bars report evmone-bench
\texttt{external}/\allowbreak\texttt{total}; compile latency below.

\input{figures/fig4-speedup}

{\sloppy
Across all 27 benchmarks, the full 83-rule set improves the geometric
mean by \textbf{+7.24\%} (95\% CI [+2.59\%, +12.11\%]). Among the
positive cases, peak speedup is \textbf{+25.79\%} on
\texttt{JUMPDEST\_n0/}\allowbreak\texttt{empty}. The \texttt{sha1}
family gains +19.59\%--+24.81\%, and
\texttt{blake2b\_}\allowbreak\texttt{huff} gains +10.41\%--+11.54\%.\par}
\noindent
Hit rate and speedup are decoupled: \texttt{mg\_mload} matches nearly
every U256 instruction yet gains under 8\%, while sha1 hits only 7.5\%
of opcodes yet gains over 20\% from x86 branch and compare-merge cleanup;
blake2b follows the same pattern. The layers complement each other:
multi-word rules concentrate gains on U256-heavy contracts, while CgIR
handles broader hardware-specific cleanups outside machine-independent
equivalence proofs.

\paragraph{Compilation Overhead.}
{\sloppy
Across 776 JIT unit-test modules, median per-module compile time is
0.45\,ms (p95 0.87\,ms; nearest-rank p99 23.59\,ms) for the full
pipeline---loading, analysis, and JIT code generation. The nearest-rank
p99 sample is a 1\,MB stress fixture; a few larger early-run outliers
remain beyond that percentile, so this is an upper-bound distribution,
not the incremental rewrite-pass cost. Isolating per-pass rewrite latency
is future work.\par}

\subsection{Shadow Audit and Statistical Validation}
\label{sec:shadow-audit}

\paragraph{Noise Floor Calibration.}
{\sloppy
We calibrate a paired benchmark noise floor in two stages: \textsc{0a}
measures within-window pairwise deltas (one prod-only build, 30 reps
$\times$ 27 benchmarks $\times$ 4 windows; $p_{99} = \mathbf{1.86\%}$),
\textsc{0b} measures inter-run deltas under the same
single-binary, environment-variable swap protocol used by the single-rule
audit benchmark ($p_{99} = \mathbf{2.65\%}$). These $p_{99}$ values use a
trimmed estimator (\texttt{trim\_frac=0.10}); untrimmed values
3.94\%/5.23\% (threshold 5.92\%) would only strengthen the null below.
With a $1.5\times$ inflation guard against carry-over correlation, the
effective threshold for declaring a per-rule speedup is
$\boldsymbol{2.80\%}$; the pilot fixes 15 reps per candidate at this
threshold ($\alpha{=}0.05$, power $0.80$, median CV $0.73\%$).\par}

\paragraph{Dual-Arm Audit on 1{,}432 Rules.}
{\sloppy
We run the matcher in two configurations on the audit-accepted subset
of 1{,}432 rules: a \emph{naive} arm with root-only swap, and an
\emph{aware} arm with recursive commutative-aware swap to depth four.
Only \textbf{1} rule (\texttt{synth-add-1907}, the identity
$\texttt{add}(x, 0)$) shows a non-zero recovery delta of \textbf{48}
additional fires across the trace---about \textbf{0.02\%} of the
217{,}325 total audit hits across the 1{,}432 rules (or 0.06\% of
\texttt{synth-add-1907}'s own 76{,}842 hits). The remaining 1{,}431
rules are cold in the benchmark trace under both arms.\par}

\paragraph{Single-Rule Bench and FDR.}
We benchmark seven pre-registered candidates (four highest-firing rules,
three negative controls). Each candidate uses 15 reps $\times$ 27
benchmarks $\times$ 2 sides, a fresh process per run, bracketed-mean
deltas, and bootstrap CIs ($B{=}10\,000$). Across 189
$(\text{rule},\text{bench})$ hypotheses, no pair satisfies all three
selection tests ($\Delta{<}{-}2.80\%$, $\text{ci\_high}{<}0$,
$q_{\text{BH}}{<}0.05$, the Benjamini--Hochberg-corrected $q$-value),
and the negative-control gate also holds (0 of 3 valid). The pipeline
records $n_{\text{picks}}=0$ (false-discovery-rate-controlled picks),
so the contribution is the methodology rather than the rule yield.
